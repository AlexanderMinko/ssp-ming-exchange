## Conventions / stack (confirm per component; some TBD)
- Java + Spring Boot 4, **Spring MVC on virtual threads** (`spring-boot-starter-webmvc`, `spring.threads.virtual.enabled`) — not WebFlux. Context (trace, MDC) is ThreadLocal: any executor that runs request work must restore it (`bidderExecutor` is wrapped with `ContextExecutorService`).
- OpenRTB version: TBD (I'll specify).
- Containerized (Docker) → ECR → EKS via Gateway API `HTTPRoute` (attached to the shared `edge/shared` Gateway), all in namespace `production`.
- **Code style (enforce on every change):**
  - **Apache Commons Lang 3** for null-safe checks: `StringUtils.isBlank/isNotBlank/isEmpty`, `ObjectUtils.isEmpty` for collections/maps. Not `s == null || s.isBlank()`.
  - **Prefer the Stream API over plain `for` loops.** Keep a loop only where a stream is clearly worse (checked exceptions, early-exit with side effects) — say why in a comment.
  - **No exceptions on the hot path** (the per-request bid flow). Expected outcomes — rejects, no-bid, bidder timeout/error — are return values, not throws (`RtbOrchestrator` returns `Optional<BidResponse>`; empty = 204). Exceptions only for genuinely exceptional failures (startup, config load, programming errors).
  - **No single-character identifiers** — variables, parameters, lambda params, loop counters included
    (`var r`, `e ->`, `for (int i …)` are out). Use a descriptive name: `response`, `bidder`, `index`. Exception: OpenRTB model fields keep their wire names (`w`, `h`).
  - **Always use curly braces** on `if` / `else` / `for` / `while` bodies, even one-liners.
- **Local vs cluster config** (decided 15/11/2026): one image, config from env. **Locations** (hosts, URLs, Mongo URI) have **no default** in `application.yaml` — the cluster value comes from the chart's ConfigMap/Secret, the laptop value from `application-local.yaml` (`SPRING_PROFILES_ACTIVE=local`). A key missing from the chart then fails startup instead of silently calling `localhost`. Tuning knobs (timeouts, toggles) keep defaults. Tests fill the gaps in `src/test/resources/config/application.yaml`.
- **Logs = one JSON object per line, ssp-backend style** (decided 16/11/2026, reworked 26/11/2026): call sites are `log.info("request rejected", kv("requestId", id))` (static import `com.ming.sspexchange.logging.LogField.kv`): a constant message, every value you filter or count on in a `kv` (lazy form `kv(key, () -> …)` when building it costs something), never in a `{}` placeholder and never hand-built JSON. `DslJsonLogbackEncoder` (dsl-json) writes `@timestamp`, `level`, `logger_name`, `thread_name`, `message`, `service_name`, the MDC (`traceId`, `spanId`), then `payload` = every `kv` field and SLF4J key-value pair, then `stack_trace`; a value that fails to serialize is written as its `toString()`. The three classes in `logging/` (`LogField`, `DslJsonLogbackEncoder`, `LogFieldConverter` for `%kvargs`) are **identical in exchange and bidders apart from the package**: change both until they move into a shared library. Request lines (26/11/2026), both from `RtbOrchestrator`'s own `log`, no dedicated logger classes or names: `log.info("received adRequest", kv("sourceId"), kv("adRequest", request))` first, before any reject (the whole OpenRTB request, unsampled: the heaviest line), and for an auction that ran `log.info("auction", kv("auction", event))` with the `@CompiledJson` `AuctionEvent` including every called bidder (`bidders`: name, outcome, latencyMs, price on the auctioned imp). In SigNoz the whole `payload` is one JSON string drawn as a tree (no flatten since 26/11/2026), so a per-bidder question is a text search (`payload CONTAINS 'gamma'`); owner's choice over one line per bidder. Request-path lines are INFO. Startup and status lines may keep `{}` placeholders. **No flat request fields** (added and removed 27/11/2026, owner's choice): the request is identified by `traceId`. Postponed proposal (27/11/2026) to switch to ssp-backend's `ScopedValue` `FlowContext`, with branch-only fields: `ssp-ming-exchange/docs/superpowers/specs/2026-11-27-flow-context-scoped-value-proposal.md` (local, `docs/` is gitignored). **Framework noise at WARN** (27/11/2026, as ssp-backend's `logback-commons-spring.xml`): `org.springframework`, `org.mongodb` and `org.apache` are WARN in every profile (`logback-spring.xml`, outside the profile blocks), so start-up chatter (DispatcherServlet init, Tomcat port, Mongo driver) is gone; their WARN/ERROR and the app's own `Started … in N seconds` line stay.
- **Local logs + traces = SigNoz in Docker Compose** (decided 17/11/2026, log path changed 26/11/2026): `ssp-ming-exchange/observability/signoz/` (copied from SigNoz Foundry v0.5.0, images pinned to the EKS versions, UI on `:3301`, OTLP on `:4317`/`:4318`). Start it as its own project: `docker compose -f ssp-ming-exchange/observability/signoz/compose.yaml up -d` (project `signoz`; through the top-level compose it becomes a second, separate project). Profile `local` writes readable text on the console (`%kvargs %kvp` after the message, in a copy of Boot's pattern: re-check after a Boot upgrade) and the same JSON lines as the cluster to `~/.ssp-ming/logs/<service>.json` (rolled at 50 MB into 3 `.json.gz`); the ingester mounts that folder read-only and tails it (receiver `filelog/apps`) with the same operator chain as the EKS/kind agents. The OTel Logback appender and its `otlpLogAppenderInstaller` bean are gone (26/11/2026). Traces still go over OTLP to `:4318`.
- **Tracing config uses Boot 4 names** (fixed 17/11/2026): `spring-boot-starter-opentelemetry` (as in bidders), `management.opentelemetry.tracing.export.otlp.endpoint` and `management.tracing.export.enabled`. The old `management.tracing.enabled` / `management.otlp.tracing.endpoint` are deprecated at level `error` and no longer bind.
- **Traces = 10% of requests, whole traces** (decided 21/11/2026 as every request, ssp-backend's design minus its sampling; sampling 0.1 on EKS since 23/11/2026): apps push OTLP/HTTP straight to `signoz-otel-collector.signoz:4318` (`OTLP_ENDPOINT`, no default in `application.yaml`; local value in `application-local.yaml`). `TracingConfig` in each app: a `Sampler` that keeps parent decisions and starts a trace only from a SERVER span (drops `@Scheduled` roots), and an `ObservationPredicate` that skips `/actuator/**`. Exchange → bidders `traceparent` is kept on purpose (unlike ssp-backend, our DSPs are ours). `TRACING_SAMPLING_PROBABILITY` is 0.1 in both charts (23/11/2026: at 1.0 and 500 rps, about 3,500 spans/s, ClickHouse fell behind and the SigNoz collector buffered 5.3 GB until it was evicted); the app default stays 1.0 for the laptop. The sampler is parent-based and the exchange's server span is every trace's root, so the exchange's value decides for the whole trace: 10% of auctions are traced completely, bidders included. The bidders' per-bid line (`BidEngine`'s logger, switched by `BID_EVENTS_LOG_LEVEL`) is off in the chart (`BID_EVENTS_LOG_LEVEL: OFF`); the exchange's `received adRequest` and `auction` lines stay (2 lines per auction since 26/11/2026, the first carrying the whole request, both unsampled). The `k8s-infra` agent parses the JSON lines and lifts MDC `traceId`/`spanId` into the log record (`trace_parser`), so logs link to traces. `TRACING_ENABLED` is `true` in both charts (flipped 22/11/2026, once SigNoz ran on EKS). `management.tracing.export.enabled` stays `true` always: Boot builds the W3C propagator only under it, so with it `false` no `traceparent` is read or sent and each service mints its own trace id (found 21/11/2026). `TRACING_ENABLED` (default `true`) maps to `management.tracing.export.otlp.enabled` and only switches sending spans.
- **Grafana dashboards = git** (decided 22/11/2026): repo `ssp-ming-monitoring` holds `dashboards/<folder>/<uid>.json`, the only source (neither Grafana persists anything). Local Compose Grafana bind-mounts it (file provider, UI edits allowed; `scripts/pull.sh <uid>` writes them back, or they die with the container). EKS: Argo CD app `grafana-dashboards` (helm repo `argocd/apps/`) renders the repo's chart into one ConfigMap per dashboard in `monitoring` (label `grafana_dashboard=1`, annotation `grafana_folder`), loaded read-only by the VM stack's Grafana sidecar (`folderAnnotation` + `foldersFromFilesStructure` set in `platform/06-monitoring.tf`). Datasource uid `VictoriaMetrics` in both Grafanas (the chart's uid; the local one changed from `victoriametrics`). `scripts/check.sh` lints.
- **Bidder client spans** (21/11/2026): named `bid <bidder>` with a `bidder` key (`BidderClientConfig#bidderObservationConvention`, the name passed as a RestClient attribute). Each call has one verdict future, settled atomically by whichever comes first: the reply (`verdict.complete` inside `exchange()`, while the client span is open) or `completeOnTimeout`. When the timeout won, the reply gets the stackless marker error `LATE_RESPONSE` on its client observation (`BidderService#settle`), so the span is an error with `outcome=TIMEOUT` and SigNoz equals `exchange_bidder_requests_total` exactly (22/11/2026; a clock check was off by ~0.1%).
- **Late bidder calls are never cancelled** (22/11/2026, as in ssp-backend): `completeOnTimeout` fixes the auction verdict, the HTTP call runs on and keeps its connection. The client read timeout (400 ms) only ends hung calls and must stay >= the largest bidder window: `MAX_TMAX_MS` 450 - `OVERHEAD_MS` 50 = 400 ms. Raise both together.
- **Synthetic data only.** All bid requests/responses are simulated — no real customer PII, no production revenue data. (Matches org data-handling rules.)
